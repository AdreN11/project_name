# Подход к работе с данными

Мы используем подход **ELT** (Extract → Load → Transform):

1. Сначала загружаем данные в ClickHouse с минимальными изменениями.
2. Типы делаем максимально «мягкими» (много Nullable), чтобы загрузка прошла успешно.
3. Очистку, приведение типов, обработку пропусков и создание аналитических полей делаем уже после загрузки — на этапе трансформации.

**Преимущества подхода:**
- быстрее начинать исследование данных;
- явно видеть проблемы качества данных;
- хранить логику очистки в SQL (воспроизводимо и прозрачно).

# Таблица `users`

## Общее
- ≈ 10 300 пользователей.
- Ключевые поля для продуктового анализа:  
  `user_id`, `subscription_plan`, `is_active`, `subscription_start_date`, `primary_device`, `country`, `age`, `created_at`.

## Качество данных
- Есть пропуски в важных полях (`age`, `monthly_spend`, `household_size` и др.).
- Присутствуют аномальные значения возраста (≤ 10 и ≥ 90).
- Дубликатов по `user_id` 300.

## Поле `created_at`
- Дата и время **создания аккаунта** пользователя.
- Может использоваться как одна из возможных точек отсчёта для когорт.
- Важно решить позже: брать когорту по `created_at` или по дате **первой активности** (первый просмотр / поиск).  
  В реальных продуктах чаще используют первую активность.

## Поле `monthly_spend`
- **Не является ценой тарифного плана.**
- Средние значения почти одинаковы across всех тарифов (Basic / Standard / Premium / Premium+ ≈ $20–24).
- Внутри каждого тарифа разброс очень большой (от ~0.1 до $800–1000).
- Поле шумное и слабо связано с `subscription_plan`.

**Продуктовый вывод:**  
Для анализа монетизации опираемся в первую очередь на `subscription_plan`, а не на `monthly_spend`.

## Устройства и география

| Поле               | Таблица                              | Смысл                                                                                                             |
|--------------------|--------------------------------------|-------------------------------------------------------------------------------------------------------------------|
| `primary_device`   | `users`                              | Основное устройство пользователя (профиль). Возможно, устройство, с которого оформляли подписку или самое частое. |
| `device_type`      | `watch_history`, `search_logs` и др. | Устройство **конкретной сессии** (с которого реально смотрели / искали).                                          |
| `country`          | `users`                              | Страна пользователя (профиль / регистрация).                                                                      |
| `location_country` | `watch_history`, `search_logs` и др. | Страна **конкретной сессии** (откуда реально смотрели / искали).                                                  |

**Важно:** это разные сущности.

- Для анализа поведения во время просмотра / поиска лучше использовать поля из событийных таблиц (`device_type`, `location_country`).
- Поля из `users` (`primary_device`, `country`) — характеристики профиля пользователя.

## Продуктовые последствия
- Для сегментации по тарифам используем `subscription_plan`.
- `is_active` — приближённый флаг текущего статуса подписки (с оговорками).
- Возраст лучше использовать в виде возрастных групп, а не как сырое число.
- `primary_device` — полезный срез на уровне пользователя, но не замена `device_type` сессии.

# Таблица `watch_history`

## Общее
- ≈ 105 000 строк (сессий просмотра).
- Ключевые поля:  
  `session_id`, `user_id`, `movie_id`, `watch_date`, `device_type`, `watch_duration_minutes`, `progress_percentage`, `action`, `location_country`.

## Качество данных

### Пропуски
| Поле                      | Количество пропусков | Доля     |
|---------------------------|----------------------|----------|
| `watch_date`              | 0                    | 0%       |
| `device_type`             | 0                    | 0%       |
| `action`                  | 0                    | 0%       |
| `location_country`        | 0                    | 0%       |
| `watch_duration_minutes`  | 12 332               | ~11.7%   |
| `progress_percentage`     | 8 514                | ~8.1%    |

### Дубликаты
- Есть дубликаты по `session_id` (несколько тысяч `session_id` встречаются более одного раза).
- Точное количество лишних строк 5000.

### Аномалии
- Значений `progress_percentage` < 0 или > 100 не обнаружено.

## Поле `action`
- Значения: `started`, `stopped`, `paused`, `completed` — распределены почти равномерно.
- Средний `progress_percentage` у всех типов action ≈ 50%.
- Поле **слабо согласовано** с реальным прогрессом просмотра.

**Продуктовый вывод:**  
Для определения факта досмотра опираемся на `progress_percentage`, а не на `action`.

## Правила для метрик
- **Completion Rate (основной)** = доля сессий с `progress_percentage >= 90`
- **Completion Rate (soft)** = доля сессий с `progress_percentage >= 80`
- Дополнительно: распределение сессий по бакетам глубины просмотра (0–10%, 10–50%, 50–80%, 80–90%, ≥90%).

## Устройства и география
- `device_type` и `location_country` в этой таблице относятся к **конкретной сессии**.
- Их следует использовать для анализа поведения, а не поля из `users`.

# Таблица `search_logs`

## Общее
- 26 500 строк.
- Ключевые поля для анализа активности: `search_id`, `user_id`, `search_date`, `device_type`, `location_country`.

## Качество данных
- Пропусков в ключевых полях (`search_date`, `user_id`, `device_type`, `location_country`) нет.
- Дубликаты: 1 500 лишних строк (25 000 уникальных `search_id`).

## Продуктовые заметки
- Используется вместе с `watch_history` для определения **активности** пользователя.
- `device_type` и `location_country` относятся к конкретной поисковой сессии.

# Таблица `movies`

## Общее
- 1 040 строк (1 000 уникальных `movie_id`).
- Ключевые поля: `movie_id`, `title`, `content_type`, `genre_primary`, `duration_minutes`.

## Качество данных
- Пропусков в `title`, `content_type`, `genre_primary` нет.
- Дубликаты: 40 лишних строк.

## Распределение content_type
- Movie — 458
- TV Series — 267
- Documentary — 142
- Stand-up Comedy — 119
- Limited Series — 54

## Жанры
Жанры распределены относительно равномерно (Adventure, War, Action, Sci-Fi, Comedy и т.д.), явного доминирующего жанра нет.

## Продуктовые заметки
- `content_type` и `genre_primary` — основные срезы для анализа вовлечённости.
- При джойнах лучше учитывать наличие дубликатов по `movie_id` (использовать `DISTINCT` или предварительно дедублицировать в витрине).
